## Figma Make — подтверждённый экран `/search`

В рабочем превью Figma Make визуально подтверждён desktop-экран поиска: верхняя навигация с логотипом «Аренда БЕЗ», выбором города и входом; вторая строка содержит сегмент «Длительный срок / Посуточно», поиск по району/адресу/метро, выпадающие фильтры «Комнаты» и «Бюджет», а также переключатель «Список / Карта». Контент разделён на левую область с результатами и правую карту с ценовыми маркерами.

Карточки в desktop-выдаче содержат бейджи «Проверено» и «Без залога», фотографию, заголовок, рейтинг, адрес/параметры, ориентир метро и месячную цену. Референс Figma Make указывает 6 объектов в Казани. Для мобильного состояния задана последовательность: закреплённая область фильтров → карта высотой около 360–380 px → одноколоночный список. Каждая мобильная карточка должна выводить горизонтальную галерею из трёх фотографий с ценой и характеристиками ниже.

### Зафиксированные корректировки макета

| Требование из истории Figma Make | Обязательное следствие для реализации |
|---|---|
| Тип аренды | Сегментированный переключатель «Длительный срок / Посуточно». |
| Комнатность | Один доступный выпадающий список вместо ряда плашек. |
| Desktop-навигация | На ширине desktop нет кнопки мобильного меню. |
| Мобильное меню | Открывается и закрывается из кнопки-бургера; не скрывается стилем поверх условного рендеринга. |
| Карта | Desktop: правая колонка; mobile: видимый верхний блок ограниченной высоты без перекрытия маркеров или pop-up. |
| Широкий экран | Контент ограничен `max-width: 1440px`; результаты имеют уменьшенный левый отступ, чтобы карта не сжималась. |

Полноэкранный preview временно выдал служебное сообщение Figma Make о необходимости перезагрузки; это не относится к пользовательскому интерфейсу и не блокирует анализ уже отрендеренного прототипа.

## Проверка Figma Prototype

Указанный интерактивный Prototype открыт с `node-id=1-5098`. Браузер подтвердил загрузку страницы и сохранил её HTML-копию для анализа, однако встроенный рендер Figma не передал скриншот и не показал доступных семантических элементов. Следующий шаг — извлечь из HTML параметры фрейма, путь встроенного prototype-viewer и данные переходов; визуальные переходы будут проверены повторно после нахождения прямого URL просмотрщика.

В исходном файле Figma визуально подтверждена последовательность из **15 фреймов**. На текущем холсте одновременно видны экраны лендинга/каталога, входа, детальных карточек и страницы владельца; выбранный 15-й фрейм — `Owner page design (Copy)`. Переходы между фреймами не следует фиксировать по приблизительным координатам: необходимо получить актуальный снимок интерфейса с доступными кнопками либо анализировать данные представления напрямую.

Навигация через встроенную кнопку «Previous frame» работает: после перехода от 15-го к 14-му экрану URL изменился на `node-id=1-4715`. Следовательно, все фреймы можно пройти последовательно и связывать с уникальными node-id для матрицы реализации. Панель инспектора обновляется с задержкой, поэтому перед фиксацией деталей каждого экрана требуется отдельное обновление состояния страницы.

**Фрейм 14/15 (`node-id=1-4715`):** мобильная колонка `402×3041 px`, auto layout по вертикали, фон `#F7F7F7`. В отличие от 15-го фрейма (`402×2996 px`), этот вариант включает `IconChevronDown`, что подтверждает отдельное состояние выбора/раскрытия, а также те же базовые визуальные активы: `IconGlobe`, `IconHome` и главное фото объекта `1200×700`. Следует реализовать его как вариант состояния, а не самостоятельную несвязанную страницу.

Нативная команда Figma «Present» сформировала прямой Prototype URL с выбранным `node-id=1-4715`, но рендер браузера снова не передал визуальный скриншот и семантические точки взаимодействия. Для обеспечения корректной реализации используются подтверждённые визуальные данные из исходного Figma canvas, свойства фреймов в инспекторе, тексты и сценарии Sprint 1, а также работающий Figma Make-предпросмотр `/search`.

После перезагрузки Dev Mode восстановил последовательность `14 / 15` и выбранный фрейм на холсте. В обзоре одновременно видны два длинных варианта страницы владельца, окно входа и две детальные карточки объектов. Это подтверждает, что исходный файл содержит набор связанных, а не изолированных экранов, однако Figma не отдаёт текстовые слои и прототипные hotspot-ы через доступный браузерный рендер.

Повторная инспекция 14-го фрейма дополнительно выявила `IconMenu (17.99×17.99)`. Это подтверждает наличие отдельной мобильной навигации в сценарии владельца; в реализации кнопка меню должна быть доступна на малой ширине и скрыта на desktop в соответствии с Figma Make.

Визуально подтверждена форма регистрации: логотип «Аренда БЕЗ», табы «Вход / Регистрация», заголовок «Создать аккаунт», обязательные поля имени и телефона, кнопка «Зарегистрироваться» и текст согласия с пользовательским соглашением и политикой конфиденциальности. По масштабу и составу это полноразмерная маршрутная страница с навигацией и несколькими секциями, которая требует отдельной реализации как один из основных mobile-маршрутов, а не модального состояния.

### Вывод по полному проходу Figma

Последовательно пройдены фреймы 1–15: desktop каталог; варианты desktop-карточек; публичные лендинги арендатора и собственника; desktop/mobile вход и регистрация; mobile каталог; полные mobile-лендинги; mobile карточки; и два близких состояния страницы владельца. Модель реализации должна строиться вокруг **семи адаптивных маршрутов** (поиск, карточка объекта, лендинг арендатора, лендинг собственника, авторизация, регистрация, кабинет владельца) с вариациями контента и UI-состояний, а не вокруг 15 независимых страниц.
